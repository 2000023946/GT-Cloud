
### V1 — Basic Workload Deployment

**Goal:**
Allow a GT student to upload code, specify what resources and networking it needs, run it on one of our machines, and see what is happening.

### V1 flow

```text
Student
   ↓
Upload code + run command
   ↓
Specify:
- CPU
- RAM
- Network rules
   ↓
Platform
   ↓
Scheduler chooses worker
   ↓
Worker runs code
   ↓
Platform monitors it
   ↓
Student sees:
- Running / completed / failed
- CPU usage
- RAM usage
```

### V1 needs

* **Workload submission**
* **Worker registration**
* **Basic scheduler**
* **Rust worker/runtime**
* **Basic CPU/RAM management + monitoring**
* **Basic networking configuration**
* **Status/output reporting**
* **Simple CLI or API**

### Not V1

No databases, GPUs, self-healing, advanced service discovery, sophisticated load balancing, Kubernetes, Docker orchestration, etc.

The core question V1 answers is simply:

> **Can a student give our platform code + requirements, have our infrastructure decide where to run it and actually run it, and let the student see what happened?**
